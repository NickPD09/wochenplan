1. Network Layer (Schicht 3) & IP

4 Grundaufgaben: Adressierung der Endgeräte · Encapsulation (Segment → Paket) · Routing · De-Encapsulation.

IP ist …

  • Connectionless – kein Verbindungsaufbau, keine ACKs/Sync vorher.
  • Best Effort – keine Garantie, kein Neusenden, weiß nicht ob Ziel online ist.
  • Media Independent – egal ob Kupfer, Glas, WLAN.

Daraus folgt

  • IP ist unreliable: kann Fehler nicht beheben, nichts neu senden, nichts sortieren → das macht TCP.
  • Die IP-Adressen ändern sich von Quelle bis Ziel nicht (Ausnahme NAT). MAC-Adressen ändern sich pro Hop!
  • MTU kommt vom Data-Link-Layer. Zu großes Paket → Fragmentierung (nur IPv4, kostet Latenz; IPv6 fragmentiert nicht).

3. Wie ein Host routet

Ein Host kann senden an: sich selbst (127.0.0.1 / ::1), lokale Hosts (gleiches LAN), remote Hosts (anderes Netz).

Entscheidung lokal/remote: eigene IP AND Subnetzmaske = eigene Netz-ID. Ziel-IP AND Maske = Ziel-Netz-ID. Gleich → lokal (direkt). Ungleich → Default Gateway.

Default Gateway (DGW)

  • Router oder Layer-3-Switch, muss eine IP im selben Netz wie das LAN haben.
  • Host kennt DGW statisch oder per DHCP (IPv6: Router Solicitation / Advertisement).
  • Im Host ist das DGW eine statische Route „last resort“ (0.0.0.0/0).
  • Ohne (oder mit falschem) DGW kommt kein Paket aus dem LAN raus.
  • Routing-Tabelle anzeigen: route print oder netstat -r (Windows).

6. IPv4-Adressen

32 Bit, hierarchisch: Netzteil + Hostteil. Die Subnetzmaske trennt beide (Bit für Bit, AND). Prefix-Länge = Anzahl der 1er in der Maske (/24).

Logisches AND: 1·1=1, sonst 0.   192.168.10.77 AND 255.255.255.0 = 192.168.10.0

Drei Adressen pro Netz

  • Netzadresse – Hostbits alle 0 (192.168.10.0)
  • Hosts – erste .1, letzte .254
  • Broadcast – Hostbits alle 1 (192.168.10.255)

Sendearten

  • Unicast – 1 Ziel
  • Broadcast – alle im Netz
  • Multicast – Gruppe, z. B. 224.10.10.5

Private Adressen (RFC 1918) – nicht im Internet routbar → NAT am Edge-Router

  • Link-Local / APIPA 169.254.0.0/16 – Windows vergibt sich selbst, wenn kein DHCP antwortet

7. Subnetting

Warum? Switches fluten Broadcasts an alle Ports, nur Router stoppen Broadcasts. Große Broadcast-Domänen = viel Traffic. Subnetting verkleinert sie, verbessert Performance, ermöglicht Security-Regeln zwischen Subnetzen. Aufteilung nach Standort, Abteilung oder Gerätetyp.

Formeln: Hosts = 2h − 2  ·  Subnetze = 2geliehene Bits  ·  Blockgröße = 256 − letztes Masken-Oktett

8. VLSM – Variable Length Subnet Mask

Beispiel: 4 LANs + 3 WAN-Links = 7 Subnetze, größtes LAN 28 Hosts → /27 (8 × 30 Hosts) passt. Aber: WAN-Links brauchen nur 2 Adressen → je 28 verschwendet, 84 gesamt.

  • VLSM = „ein Subnetz nochmal subnetten“ → das letzte /27 in acht /30 zerlegen.
  • Regel: immer mit dem größten Host-Bedarf beginnen, dann absteigend bis zum kleinsten.
