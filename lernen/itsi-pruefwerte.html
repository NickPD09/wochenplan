Muss man zeichnen können

Merkle-Damgård-Konstruktion (MD5, SHA-1, SHA-2)

f : {0,1}a+b → {0,1}b
m̄ = m1 ‖ m2 ‖ … ‖ mn   mit |mi| = a
H0 = IV
Hi := f(Hi−1 ‖ mi)   1 ≤ i ≤ n
  1. Oben eine lange Box: m₁ | m₂ | … | mₙ₋₁ | mₙ.
  2. Darunter eine Reihe von f-Boxen (Trapeze), eine pro Block.
  3. Jeder Block mᵢ: Pfeil runter, dann rechts ins f.
  4. IV → erstes f, dann f → f → … (in der Mitte strichliert).
  5. Letztes f → strichlierte Box „final“ → Hash.

Merksatz: Neuer Block + alter Zwischenwert → f → neuer Zwischenwert. Davor wird die Nachricht gepaddet, damit sie ein Vielfaches von a ist. SHA-3 nutzt stattdessen die Sponge-Konstruktion.

Wahrscheinlichkeit

Birthday-Paradoxon

Hash mit n Bit hat N = 2n mögliche Werte. Aufwand für eine Kollision:

√(2n) = 2n/2
P(Kollision) ≈ 1 − e−k² / 2N
P = 50 %  ⇒  k ≈ 1,18 · √N

k = Anzahl gehashter Nachrichten. Beispiel: N = 365 Tage ⇒ k ≈ 1,18 · √365 ≈ 23 Personen.

Folie 13

Message Authentication Codes (MAC)

Hashfunktion alleine: Integrität ✔, Authentizität ✘, weil jeder den Hash neu berechnen kann. Lösung: einen geheimen Schlüssel einbeziehen.

MACk(M) = f(k, M)
M = Nachricht, k = geheimer Schlüssel
  • MAC = Prüfwert mit Schlüssel.
  • Nur wer k kennt, kann einen gültigen MAC erzeugen.
  • Der Empfänger prüft den MAC, indem er ihn neu berechnet.
Folie 14

HMAC (Hash-based MAC)

Ein MAC, der auf einer Hashfunktion aufbaut (z. B. SHA-256).

HMACk(M) = H( (k′ ⊕ opad) ‖ H( (k′ ⊕ ipad) ‖ M ) )
⊕ = XOR, ‖ = aneinanderhängen, ipad/opad = feste innere/äußere Padding-Konstanten
VorteileEinfach zu implementieren. Bewiesen sicher, also so stark wie die Hashfunktion.
AnwendungenTLS (Prüfsummen für verschlüsselte Nachrichten), APIs (Requests mit HMAC + Zeitstempel), JWTs, Banking/IoT (Befehle und Sensordaten).
